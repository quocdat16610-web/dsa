# Đệ quy có nhớ & Quy hoạch động

## 1. Từ đệ quy tới QHĐ
`F(n) = F(n-1) + F(n-2)` viết đệ quy trực tiếp có độ phức tạp **mũ** vì cùng một `F(k)` bị tính lại rất nhiều lần.
- **Đệ quy có nhớ (memoization):** lưu kết quả vào mảng, lần sau gọi lại thì trả luôn.
- **QHĐ từ dưới lên (tabulation):** tính `dp` theo thứ tự sao cho khi tính `dp[i]` thì các giá trị cần dùng đã có.

```cpp
long long memo[N]; bool done[N];
long long F(int n) {
    if (n <= 1) return n;
    if (done[n]) return memo[n];
    done[n] = true;
    return memo[n] = F(n - 1) + F(n - 2);
}
```

## 2. Bốn bước thiết kế QHĐ
1. **Trạng thái:** `dp[i]` (hoặc `dp[i][j]`...) nghĩa là gì? (ví dụ "chi phí nhỏ nhất để tới hòn đá `i`").
2. **Công thức truy hồi:** `dp[i]` tính từ các trạng thái nhỏ hơn như thế nào.
3. **Cơ sở:** giá trị ban đầu (`dp[0]`, `dp[1]`).
4. **Thứ tự tính và đáp án.**

## 3. Các dạng cơ bản
- **Dãy:** ếch nhảy `dp[i] = min(dp[i-1] + |h_i - h_{i-1}|, dp[i-2] + ...)`; trộm nhà `dp[i] = max(dp[i-1], dp[i-2] + a_i)`.
- **Đổi tiền:** ít xu nhất `dp[v] = 1 + min dp[v - c]`; đếm cách có thứ tự (vòng ngoài là tổng) và không thứ tự (vòng ngoài là đồng xu).
- **Lưới:** `dp[i][j] = a[i][j] + max(dp[i-1][j], dp[i][j-1])`.
- **QHĐ đoạn:** `dp[l][r]` tính theo độ dài đoạn tăng dần (nhân dãy ma trận, trò chơi lấy số đầu/cuối).
- **QHĐ bitmask:** `dp[mask]` — tập đã chọn (phân công công việc, người du lịch `n ≤ 16`).
- **QHĐ trên cây:** `dp[u]` tính từ các con (tập độc lập lớn nhất).

## 4. Ví dụ: đổi tiền ít xu nhất
```cpp
vector<int> dp(x + 1, INF); dp[0] = 0;
for (int v = 1; v <= x; v++)
    for (int c : coins) if (c <= v && dp[v - c] + 1 < dp[v]) dp[v] = dp[v - c] + 1;
```

## Lỗi thường gặp
- Tham lam (lấy đồng lớn nhất trước) **không** đúng với mọi bộ mệnh giá — phải QHĐ.
- Khởi tạo sai (`INF` quá nhỏ hoặc cộng `INF + x` bị tràn).
- Đệ quy có nhớ quá sâu gây tràn ngăn xếp — chuyển sang vòng lặp.
