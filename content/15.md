# Sparse table (bảng thưa)

## 1. Ý tưởng
`st[j][i]` = kết quả trên đoạn dài `2^j` bắt đầu tại `i`:
```cpp
for (int i = 0; i < n; i++) st[0][i] = a[i];
for (int j = 1; (1 << j) <= n; j++)
    for (int i = 0; i + (1 << j) <= n; i++)
        st[j][i] = min(st[j-1][i], st[j-1][i + (1 << (j-1))]);
```
Xây `O(n log n)` thời gian và bộ nhớ.

## 2. Truy vấn O(1) với phép toán luỹ đẳng
Phép toán `f` luỹ đẳng nếu `f(x, x) = x`: `min`, `max`, `gcd`, `AND`, `OR`. Khi đó đoạn `[l, r]` được phủ bởi **hai đoạn chồng nhau** dài `2^k`:
```cpp
int k = __lg(r - l + 1);
int ans = min(st[k][l], st[k][r - (1 << k) + 1]);
```
Với phép **không** luỹ đẳng (tổng), có thể ghép `O(log n)` đoạn rời nhau — nhưng khi đó tiền tố/BIT tốt hơn.

## 3. Khi nào dùng?
Mảng **tĩnh** (không cập nhật), rất nhiều truy vấn. Nếu có cập nhật ⇒ cây phân đoạn.

## 4. Kết hợp tìm kiếm nhị phân / hai con trỏ
`gcd(a_l..a_r)` không tăng khi `r` tăng; `OR` không giảm ⇒ hai con trỏ hoặc tìm kiếm nhị phân, mỗi bước hỏi bảng thưa `O(1)`.

## 5. Nhảy nhị phân (binary lifting)
Cùng tư tưởng "luỹ thừa 2": `up[j][v]` = đi `2^j` bước từ `v` (trên đồ thị hàm, trên mảng `nxt`, trên cây).
```cpp
for (int j = 1; j < LOG; j++) for (int v = 0; v < n; v++) up[j][v] = up[j-1][ up[j-1][v] ];
// đi k bước: duyệt các bit của k
```

## Lỗi thường gặp
- Dùng sparse table cho tổng với hai đoạn chồng nhau (đếm trùng!).
- Tính `log` bằng hàm số thực — dùng `__lg` hoặc bảng `lg[]` tính sẵn.
